# Цель работы

Изучение посредством Wireshark кадров Ethernet, анализ PDU протоколов
транспортного и прикладного уровней стека TCP/IP.

# Задание

1. Изучение возможностей команды ipconfig для ОС типа Windows (ifconfig
для систем типа Linux).
2. Определение MAC-адреса устройства и его типа
3. Установить на домашнем устройстве Wireshark.
4. С помощью Wireshark захватить и проанализировать пакеты ARP и ICMP
в части кадров канального уровня.

Для получения информации о сетевых интерфейсах на компьютере была использована команда ifconfig. Поле ether содержит MAC-адрес сетевого интерфейса. Поле inet содержит IPv4-адрес устройства. Поле netmask определяет маску подсети, а broadcast содержит широковещательный адрес сети. Далее я узнал непосредственно Айпи адрес и адрес шлюза.(рис. [-@fig:001]).

![Айпи адрес устройства и шлюза](image/1.png){#fig:001 width=70%}

Затем я определил мак адрес шлюза.(рис. [-@fig:002]).

![мак адрес шлюза](image/2.png){#fig:002 width=70%}

MAC-адрес представляет собой 48-битный адрес, записываемый в шестнадцатеричной системе счисления в виде шести байтов.
50:ff:20:31:b1:12
Первые три байта MAC-адреса образуют OUI (Organizationally Unique Identifier). Эта часть адреса используется для идентификации организации или производителя, которому выделен соответствующий диапазон MAC-адресов.

Последние три байта используются для идентификации конкретного сетевого интерфейса в соответствующем диапазоне адресов

В моем случае мак адрес индивидуальный, глобально администрируемым.

## Анализ ARP

ARP (Address Resolution Protocol) используется для определения MAC-адреса устройства по известному IPv4-адресу в пределах локальной сети.
При необходимости передачи пакета шлюзу компьютер должен знать не только его IP-адрес, но и MAC-адрес.
Для этого используется ARP Request.
В Ethernet II заголовке ARP-запроса в качестве MAC-адреса назначения обычно используется:
ff:ff:ff:ff:ff:ff
Это широковещательный MAC-адрес.

Он означает, что Ethernet-кадр должен быть доставлен всем устройствам соответствующего локального сегмента.

Для ARP Request поле Opcode имеет значение request.
Для ARP Reply оно имеет значение reply.(рис. [-@fig:008]).

![Arp](image/8.png){#fig:008 width=70%}

Для анализа DNS был использован фильтр dns.DNS используется для преобразования доменных имён в IP-адреса.

Например, перед установлением соединения с сервером по доменному имени клиенту необходимо определить IP-адрес соответствующего сервера.
В DNS-запросе указывается имя узла, для которого необходимо получить сетевой адрес.
DNS обычно использует UDP, поэтому в захваченном пакете присутствует заголовок UDP.(рис. [-@fig:011]).

![dns](image/11.png){#fig:011 width=70%}

Для исследования протокола QUIC был выполнен захват соответствующего сетевого трафика.
QUIC является транспортным протоколом, работающим поверх UDP.

Упрощённая структура передачи имеет вид

HTTP/3
   ↓
 QUIC
   ↓
 UDP
   ↓
 IP
   ↓
 Ethernet/Wi-Fi
В отличие от классической схемы HTTP поверх TCP, QUIC использует UDP в качестве основы транспортной передачи.

При анализе пакета были исследованы сведения о QUIC-соединении и содержащиеся в нём поля.(рис. [-@fig:012]).

![quic](image/12.png){#fig:012 width=70%}
